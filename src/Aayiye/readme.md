## Overview

TourKaro ek full-stack web application hai jo Bihar ke Kaimur jile ke tourists ke liye banaya gaya hai. Ye platform:

- **Location-aware** trending places dikhata hai (GPS/IP se location detect karke)
- **AI-generated** jagah ki information provide karta hai (Google Gemini)
- **Smart search** feature hai jo web search + ML summarization use karta hai
- Users **photos aur videos** share kar sakte hain
- **AI chatbot** travel ki madad karta hai (SSE streaming)
- **Itinerary planner** with cost estimation
- **Festival calendar** with event memories

---

## Features

| Feature | Description |
|---|---|
| 🌍 Location Detection | GPS + IP-based geolocation, reverse geocoding via OpenStreetMap Nominatim |
| 🔥 Trending Places | Gemini AI se area-specific top tourist places, cached in MongoDB |
| 🔍 Smart Search | Multi-provider web search → ML summarization → Gemini fallback |
| 🤖 AI Chatbot | Streaming chatbot (SSE) powered by the Python ML service |
| 📸 Media Explore | Community-uploaded images & videos with infinite scroll |
| 📅 Travel Planner | Add places to cart, optimize route (Nearest Neighbour TSP), cost estimate |
| 🏛️ Place Detail | Per-place pages with gallery, culture, hotels, safety, maps |
| 📖 Learn More | Category-level pages generated by Gemini with web sourcing |
| 🎉 Festival Calendar | Real-time festival info with "Share Your Memory" feature |
| 👤 User Profile | Upload posts (image/video), edit profile, view own posts |
| 🔐 Auth | Email/password + Google OAuth + Facebook OAuth |
| 📊 Admin Panel | Google Sheets integration for places and category cache |

## Tech Stack

### Backend
| Layer | Technology |
|---|---|
| Server framework | **Express.js v4** |
| Template engine | **EJS** |
| Database | **MongoDB** (native driver + Mongoose) |
| Session store | **connect-mongodb-session** |
| Cache | **Redis** (optional, graceful fallback to DB) |
| Auth | **Passport.js** (Google OAuth 2.0, Facebook OAuth) |
| File upload | **Multer** + **Cloudinary** |
| AI | **Google Gemini API** (`@google/genai`) |
| Web search | Google Custom Search, Bing, SerpAPI, DuckDuckGo (failover chain) |
| HTTP client | **Axios** |
| Scheduler | **node-cron** |
| Spreadsheet | **Google Sheets API** (googleapis) |

### Frontend
| Technology | Usage |
|---|---|
| Vanilla JS | All interactivity |
| Vanilla CSS | Styling (no framework) |
| EJS | Server-side templating |
| SSE (EventSource) | Real-time chatbot streaming |

### Python ML Service
| Component | Detail |
|---|---|
| Endpoint | `http://127.0.0.1:8000` (configurable via `ML_SERVICE_URL`) |
| Used for | `/web-summarize` — scrape & summarize URLs, chatbot responses |
| Auto-start | Node.js spawns Python process on startup (`pythonAutostart.js`) |

## Getting Started

### Prerequisites

- **Node.js** v18+
- **MongoDB** (local or MongoDB Atlas)
- **Redis** (optional — graceful fallback to in-memory store if Redis is offline)
- **Python 3.9+** (for the AI/ML service)
- **API Keys** (see [Environment Variables](#environment-variables) section below)

### Installation & Setup

TourKaro consists of two main components: the Express.js Node server and the FastAPI Python ML service. Follow these steps to set up both:

#### 1️⃣ Clone the Repository
```bash
git clone <repo-url>
cd tourKaro
```

#### 2️⃣ Setup Python ML Server
It is highly recommended to use a Python virtual environment (`venv`) to run the ML service. The Node.js server is pre-configured to look for Python in this virtual environment on startup.
```bash
# Navigate to python server directory
cd tourKaro_python_server

# Create a virtual environment named 'venv'
python -m venv venv

# Activate the virtual environment:
# On Windows (CMD / PowerShell):
.\venv\Scripts\activate
# On Linux / macOS:
source venv/bin/activate

# Install required dependencies
pip install -r requirements.txt

# Create .env file for the Python server (optional, but recommended if you want separate API keys)
cp ml_service/.env.example .env
```

#### 3️⃣ Setup Express.js (Node.js) Server
```bash
# Navigate to the main redesign directory
cd ../tourKaro_reDesign

# Install Node dependencies
npm install

# Create environment configuration file
cp .env.example .env
# Open the .env file and fill in your actual credentials and API keys (Gemini, Cloudinary, etc.)
```

#### 4️⃣ Seed Places Database
To populate your MongoDB and Google Sheets with initial tourist places:
```bash
# Run the seed script in the tourKaro_reDesign directory
node scripts/seedPlaces.js
```

## Running in Development

### Option A: Monorepo Start (Auto-Start Python Server)
If `PYTHON_AUTOSTART=true` is set in your `.env` file, the Express application will automatically launch the Python ML server on startup using the executable inside `tourKaro_python_server/venv`.

Simply start the main app:
```bash
# Run inside tourKaro_reDesign
npm start
```
*The main server will run on http://localhost:5500.*

### Option B: Start Services Separately
If you want to run them in separate terminals for debugging or independent logs:

**Terminal 1 (Python ML Server):**
```bash
cd tourKaro_python_server
# Activate virtual environment:
# Windows: .\venv\Scripts\activate  |  Linux/macOS: source venv/bin/activate
uvicorn ml_service.main:app --host 127.0.0.1 --port 8000
```

**Terminal 2 (Express.js Node Server):**
```bash
cd tourKaro_reDesign
npm start
```

### Additional Scripts

| Script | Command | Description |
|---|---|---|
| Main Node App | `npm start` | Runs Express server with nodemon |
| Backend API Only | `npm run start:api` | Runs secondary backend API layer |
| Import CSV data | `npm run migrate:csv` | Migrates CSV places data to MongoDB |
| Import NoSQL data | `npm run migrate:virtual-nosql` | Migrates legacy virtual NoSQL records to MongoDB |
| Background Jobs | `npm run jobs` | Executes cron jobs manually |
| Weather Forecast | `npm run weather:home` | Fetches/caches weather forecast data |

| Method | Route | Description |
|---|---|---|
| `GET` | `/search?q=<query>` | Trie + catalog search, returns JSON array |
| `GET` | `/autocomplete?q=<query>` | Trie-based autocomplete suggestions |
| `GET` | `/api/search/smart?q=<query>` | Full smart search → structured JSON content |

**Smart Search Response:**
```json
{
  "success": true,
  "fromCache": false,
  "query": "Maa Mundeshwari Temple",
  "content": {

    "visitorInfo": { "bestTime": "Oct-Mar", "timings": "...", "nearby": [] },
    "images": ["url1", "url2"],
    "sourceUrls": [{ "title": "...", "url": "..." }]
  },
  "sourceUrls": []
}
```

## Services & Modules

### Smart Search Pipeline (`searchonweb/`)

```
User query
    │
    ▼
searchOrchestrator.searchWeb()
    ├── 1️⃣ Google Custom Search  ──► results?
    ├── 2️⃣ Bing Web Search        ──► results?  (if Google fails)
    ├── 3️⃣ SerpAPI               ──► results?  (if Bing fails)
    └── 4️⃣ DuckDuckGo            ──► results?  (if SerpAPI fails)
                                         │
                              selectSummarizationTargets()
                              (prefers gov.in, wikipedia, etc.)
                                         │
                              Python ML /web-summarize
                                         │
                              ❌ ML failed? → geminiLearnMoreFallback()
                                         │
                              Image fallback:
                              fetchUserPostImages() from MongoDB posts
```

### Gemini Service (`trending/googleGemini.js`)

- `runGemini(prompt)` — Returns trending places as JSON array, enriched with Wikipedia images
- `geminiSearchOnly(prompt)` — Direct JSON generation without Wiki enrichment

### Location Pipeline (`config.js / GET /`)

```
Request → GPS session? 
    ├── No  → render with default Kaimur data
    └── Yes → getAreaName() [Nominatim reverse geocode]
                    │
                    ▼
              findAreaCache() [MongoDB location_cache]
                    ├── HIT  → render cached trendData
                    └── MISS → Gemini.runGemini() → saveAreaCache() → render
```

### Search Cache (`services/searchCache.service.js`)

- MongoDB collection: `search_cache`
- Key: normalized query string
- TTL: configurable
- Used by both `/api/search/smart` and `/learn-more`

### Chat Memory (`backend/services/memoryService.js`)

- Stored in **Redis** (per session ID)
- Fallback: in-memory if Redis unavailable
- Cleared via `DELETE /api/chat/memory`

## Smart Search System

The smart search works as a **3-tier pipeline**:

### Tier 1 — Cache Check
- MongoDB `search_cache` collection check karta hai
- Hit hone par immediately serve karta hai

### Tier 2 — Web Search + ML Summarization
```
Multi-provider search (Google → Bing → SerpAPI → DuckDuckGo)
    → URL scoring (prefers gov.in, Wikipedia, etc.)
    → Top 3 URLs to Python ML service /web-summarize
    → Structured JSON content returned
```

### Tier 3 — Gemini Fallback
- Agar sab web search providers fail karein ya ML service down ho
- Gemini directly structured travel content generate karta hai
- Agar Gemini ke paas images nahi hain → MongoDB posts se user-uploaded images use karta hai

## AI & ML Integration

### Google Gemini
- Model: `gemini-2.5-flash` (configurable via `GEMINI_MODEL`)
- Uses: homepage trending, category pages, place detail, learn-more fallback
- Always returns strict JSON (`responseMimeType: "application/json"`)

### Python ML Service
- Runs at `http://127.0.0.1:8000`
- Endpoints used:
  - `POST /web-summarize` — Given URLs + query → structured travel content JSON
  - `POST /recommend` — (legacy) place recommendations
  - `GET /chat` / streaming — AI chatbot responses
- Node.js auto-starts the Python process via `pythonAutostart.js`

### Wikipedia Integration
- `wikiImagecontent.js` — Wikipedia API se place images fetch karta hai
- Har Gemini result ke saath Wikipedia enrichment hoti hai (with 1s delay between requests)
